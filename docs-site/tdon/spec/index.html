1 设计原则Design principles

编号Clause条款Rule
TDON-1.1纯声明式：不携带可执行代码（无 script、无事件、无任意 CSS 表达式）。Purely declarative: no executable code, no events, no arbitrary CSS expressions.
TDON-1.2所有颜色/字体/间距值必须来自当前主题令牌；内嵌具体色值视为非法。All color/font/spacing values must come from theme tokens; inline literals are illegal.
TDON-1.3加载时全量校验后再注册；校验失败不得部分生效。Validate fully before registering; a failed validation must not partially apply.
TDON-1.4可托管于任意 URL 或本地路径，不绑定特定仓库或服务。Hostable anywhere (URL or local path); no repository/service binding.
TDON-1.5specVersion 必填；未知版本直接拒绝，不猜测兼容。specVersion is required; unknown versions are rejected without guessing.
TDON-1.6校验器零第三方依赖，不得引入需要运行时求值的 schema 编译器。Zero third-party deps; no runtime-evaluating schema compiler.
TDON-1.7规模分两级阈值：软阈值警告、硬阈值报错；硬阈值须远高于真实需求。Two-level caps: soft warns, hard errors; hard must sit far above real needs.

5 预览声明Preview

编号Clause条款Rule

TDON-5.11raw-text 的 \n → <br>，其余转义。raw-text turns \n into <br>; everything else escaped.
TDON-5.12hero/card 可带 imageUrl：仅 https://、≤2048 字符。hero/card may carry imageUrl: https only, ≤2048 chars.
TDON-5.13图片以 loading="lazy" + no-referrer 渲染；校验阶段零请求。Images render with lazy loading and no-referrer; validation issues zero requests.

8 校验与加载流程Validation & loading flow

fetch (URL via fetchText port / local FileReader)
  → UTF-8 + size check (soft warn / hard error)
  → JSON.parse                (E_JSON)
  → specVersion routing       (E_VERSION)
  → structural validation     (§2–§7, up to 20 issues)
  → token resolution          (needs the current theme)
  → constraints assertions    (§7)
  → register as a custom export target
编号Clause条款Rule
TDON-8.1收集多错误（≤20 条），每条含 code / path / 双语 message。Collect multiple issues (≤20), each with code/path/bilingual message.
TDON-8.2结果分 errors（阻断）与 warnings（提示但可用）。Results split into errors (blocking) and warnings (usable with a note).
TDON-8.3主题变更导致令牌不可解析时，不清空已注册目标，只标记不可导出。If a theme change breaks a token, keep the target registered and only mark it non-exportable.

11 安全边界Security boundary

编号Clause条款Rule
TDON-11.1路径穿越：渲染与打包各自校验（不信任单点校验）。Path traversal: rendering and packaging each validate independently.
TDON-11.2HTML 注入：文本全转义、属性走白名单、不允许 style 字符串。HTML injection: escape all text, whitelist attributes, no style strings.
TDON-11.3原型污染：按键白名单重建；__proto__/constructor/prototype → E_BAD_KEY。Prototype pollution: rebuild by key whitelist; those keys → E_BAD_KEY.
TDON-11.4资源耗尽：文件 4 MB / 节点 1500 / 文件 64；超硬阈值在校验阶段拒绝。Exhaustion: 4 MB file / 1500 nodes / 64 files; hard caps rejected at validation.
TDON-11.5正则全部为常量、无嵌套量词（无 ReDoS 面）。All regexes constant with no nested quantifiers (no ReDoS surface).
TDON-11.6URL 取回复用 fetchText 端口（http/https、10s、512 KB）。URL fetch reuses the fetchText port (http/https, 10s, 512 KB).
TDON-11.7远程资源仅 imageUrl 与预留的 fontUrl；必须 https；校验阶段零请求。Remote resources limited to imageUrl plus the reserved fontUrl; https only; zero requests during validation.
TDON-11.8不做远程 $ref/$schema 求值（不使用 JSON Schema）。No remote $ref/$schema evaluation (JSON Schema is not used).

14 TDOT 模板语言TDOT template language

TDOT = Theme Design Object Template。TDON 保持纯声明；需要逻辑的目标走 TDOT，由受限解释器在沙箱内求值（能力白名单，无任意 JS）。自 `tdot-0.1` 起 template 段真正生效：specVersion 恰为 tdot-0.1 时才求值，其他 tdot-* 版本报 E_TDOT_VERSION（前向兼容：新版本不会被旧运行时错误解释）。TDOT = Theme Design Object Template. TDON stays declarative; targets needing logic move to TDOT, evaluated by a restricted interpreter in a sandbox (capability whitelist, no arbitrary JS). Since `tdot-0.1` the template block is live: it evaluates only when specVersion is exactly tdot-0.1; any other tdot-* version yields E_TDOT_VERSION — forward compatibility, so a newer version is never silently misread by an older runtime.

"template": {
  "specVersion": "tdot-0.1",   // 独立版本串 / own version string
  "data": { "features": [ … ] },
  "body": "…"                  // 模板正文（≤64 KB），支持 {{ }} 插值与 #if/#each 块
}
编号Clause条款Rule
TDON-14.1template 为 TDOT 专属命名空间，内容由 TDOT 规范定义。template is the TDOT namespace; its content is defined by the TDOT spec.
TDON-14.2不带 tdot- 前缀的 specVersion 只接受并警告 W_TDOT_RESERVED，不报错。A specVersion without the tdot- prefix is accepted with W_TDOT_RESERVED only — never an error.
TDON-14.3TDOT 能力边界见 ADR-011；扩展能力须先改 ADR 再改实现。TDOT's capability boundary lives in ADR-011; extend the ADR before the implementation.
TDON-14.4TDOT 不得削弱 §10.2 的禁止项。TDOT must not weaken the prohibitions in §10.2.

能力白名单：变量、#if/#each、六种比较、+/- 算术、字面量、! 取反、@build.* 宿主占位符。明确不提供函数调用、*///%、正则、闭包、赋值、include/import 与任意 JS。Capability whitelist: variables, #if/#each, six comparisons, +/- arithmetic, literals, ! negation, and @build.* host placeholders. Explicitly absent: function calls, *///%, regex, closures, assignment, include/import, and arbitrary JS.

非确定性由宿主注入：@build.year/date/timestamp/random 是占位符，值由调用方（Theme Builder）写入，解释器本身不读时钟也不取随机数——因此同一文档 + 同一注入值必然产出同一结果，可测试、可复现。Non-determinism is host-injected: @build.year/date/timestamp/random are placeholders filled by the caller (Theme Builder); the interpreter reads no clock and draws no random numbers — same document plus same injected values always yields the same output, so it is testable and reproducible.

三道上限：表达式嵌套 8 层、节点 2000、求值步数 10000；借它们把"模板写错"变成可读的错误码而不是卡死。Three caps: expression depth 8, 2000 nodes, 10000 evaluation steps — they turn "bad template" into a readable error code instead of a hang.
