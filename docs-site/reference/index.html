参考及开发文档

面向二次开发者与集成方。完整架构决策（ADR）与过程材料见仓库内说明。

1 · 仓库结构

mono-repo，四包各自独立构建、测试与发布：

包职责许可证
HIA/core公共核心：主题模型、配色算法（Oklch）、关系规则推导、Token 导出适配器、宝典数据。三端以本地包链接复用。MIT
HIA/web网页版（Vite），共享渲染器为三端 UI 单一事实来源，部署 GitHub Pages。MIT
HIA/electronElectron 桌面版：复用 web 渲染产物，隐藏 BrowserWindow 真实渲染取色。Apache-2.0
HIA/tauriTauri 桌面版：Rust 后端 chromiumoxide 采集，CDP 逐请求 SSRF 拦截。MIT

2 · 主题模型契约（摘要）

完整契约见 HIA/core/src/types.ts 与 ADR-007（配色关系模式与辅助色）：

字段类型语义
primary / secondary / thirdColorRoleColor主体色成员；RoleColor = { name, value, scale(50..900), on }，色阶由 HEX 重建。
seriesMode'single'|'dual'|'triad'主体色模式，由成员数派生（装配语义：缺省补默认）。
seriesRelationSeriesRelationId十种关系规则之一（manual/complement/clash/neutral/analogous/split-complement/tertiary/primary-combo/secondary-combo/pure）。
auxiliaryRoleColor[]辅助色独立维度，0..8 槽位，与主体色模式无关。
gradientsGradientSettings8 渐变角色；family 支持 ColorFamily | 'third' | 'aux${number}'。
向后兼容原则：旧数据缺字段一律按 dual/manual/空辅助槽补默认；ThemeInput 与 Preset 均可选携带新字段，清洗层（sanitizePreset）做白名单校验并由 HEX 重建色阶。

3 · core API 速览

import {
  buildTheme, createThemeDraft, presetFromDraft, draftFromPreset,
  deriveSecondaryByRelation, deriveThirdByRelation, generateAuxiliaryCandidates,
  exportThemeCss, exportThemeJson, getExportTarget,
  encodeShareHash, decodeShareHash, buildSharePayload,
  parseThemePack, mergeImportedPresets, serializeThemeLibrary,
  FORM_PACKS, BAODIAN_PALETTE, SERIES_RELATION_DEFS,
} from '@hia/theme-core';
  • buildTheme(input)：装配主题（推导第三色/副色变体/空辅助槽），全部色阶在此计算；
  • deriveSecondaryByRelation / deriveThirdByRelation：按规则从主色推导副色与第三色；
  • encodeShareHash / decodeShareHash：分享链接编码（紧凑位置数组，缺省字段省略）；
  • parseThemePack：远程/导入主题包清洗（含 v2 契约字段白名单与截断）。

4 · Token 结构（CSS 变量）

导出的 CSS 变量遵循分层命名：

--hia-primary-50 … --hia-primary-900   /* 主色十档 */
--hia-secondary-*, --hia-third-*        /* 副/第三色族 */
--hia-aux0-50 … --hia-auxN-900          /* 辅助色槽位（N 为索引） */
--hia-on-primary / --hia-on-aux0        /* 前景对比色（WCAG 自动选择） */
--hia-fs-h1 / --hia-line-height-body    /* 字号与行高令牌（ADR-006） */

运行时（预览区）另有 --p/--s/--t/--a{N} 前缀的快捷变量供 mock 与渐变消费。

5 · 导出适配器

  • WordPress：theme.json（v2+）色板含全部色族 + 子主题骨架 ZIP；
  • Tailwind：tailwind.config 片段，colors 按 primary/secondary/third/aux{N} 族映射；
  • CSS/JSON：通用令牌导出（默认/经典/TDON 三种支持模式，TDON 为声明式适配草稿规范）。

6 · 桌面端架构与取色

两端共享同一 scanner bundle（HIA/extractor/dist/browser-scanner.bundle.js，IIFE 自包含），保证评分一致；构建校验脚本断言三端内容哈希一致。

  • Electron：隐藏隔离 BrowserWindow 加载目标页 → 稳定化（网络/渲染双重静默）→ 注入 scanner 采集 DOM 证据 → 量化评分；finally 销毁窗口；
  • Tauri：Rust 后端 chromiumoxide launch（显式无头）→ CDP Fetch 域逐请求 SSRF 裁决（重定向每跳 DNS 深度校验，命中即阻断）→ 采集后 Browser.close 带超时护栏，函数返回经 Drop/kill_on_drop 强杀子进程，杜绝残留窗口；
  • SSRF 防线：协议白名单 → 私网/保留 IP 字面量 → 连接时 DNS 深度解析（fail-closed）→ CDP 逐请求裁决（Electron 为 webRequest 同口径）。

7 · 二次开发

推荐环境：Node 22 LTS（仓库 .mise.toml 锁定，mise install）、PowerShell 7（Windows）、Rust stable（仅 Tauri）。

# 构建 core 并跑全部单测
cd HIA/core && npm install && npm run build && node --test test/
# 网页版开发服务器
cd HIA/web && npm install && npm run dev
# Electron / Tauri
cd HIA/electron && npm install && npm start
cd HIA/tauri && npm install && npm run build

代码约定：全部语义节点中英双语文档化注释（ROP）；三端渲染器产物哈希一致性由 CI 断言；新增第三方依赖须登记来源/版本/许可证并优先宽松许可。
