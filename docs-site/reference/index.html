2 · 主题模型契约（摘要）2 · Theme Model Contract (summary)

完整契约见 HIA/core/src/types.ts 与 ADR-007（配色关系模式与辅助色）：The full contract is in HIA/core/src/types.ts and ADR-007 (harmony modes & auxiliary colors):

字段Field类型Type语义Semantics
primary / secondary / thirdColorRoleColor主体色成员；RoleColor = { name, value, scale(50..900), on }，色阶由 HEX 重建。Body-color members; RoleColor = { name, value, scale(50..900), on } with scales rebuilt from HEX.
seriesMode'single'|'dual'|'triad'主体色模式，由成员数派生（装配语义：缺省补默认）。Body mode, derived from member count (assembly semantics: missing → default).
seriesRelationSeriesRelationId十种关系规则之一（manual/complement/clash/neutral/analogous/split-complement/tertiary/primary-combo/secondary-combo/pure）。One of ten rules (manual/complement/clash/neutral/analogous/split-complement/tertiary/primary-combo/secondary-combo/pure).
auxiliaryRoleColor[]辅助色独立维度，0..12 槽位，与主体色模式无关。Independent auxiliary dimension, 0..12 slots, unrelated to the body mode.
gradientsGradientSettings8 渐变角色；family 支持 ColorFamily | 'third' | 'auxN'（N 为槽位索引）。Eight gradient roles; family accepts ColorFamily | 'third' | 'auxN' (N = slot index).
向后兼容原则：旧数据缺字段一律按 dual/manual/空辅助槽补默认；ThemeInput 与 Preset 均可选携带新字段，清洗层（sanitizePreset）做白名单校验并由 HEX 重建色阶。Backward compatibility: missing fields default to dual/manual/empty aux. ThemeInput and Preset carry the new fields optionally; the sanitize layer (sanitizePreset) whitelists values and rebuilds scales from HEX.

  • buildTheme(input)：装配主题（推导第三色/副色变体/空辅助槽），全部色阶在此计算；buildTheme(input): assembles the theme (derives third/secondary variant/empty aux); all scales are computed here;

无障碍工具（W-tb-P36 新增）：contrastMatrix(entries) 全调色板两两对比（WCAG 对称 + APCA 带符号方向矩阵）；stepForContrast(base, bg, target) 保色相沿亮度二分至目标比值（不可达返回最接近值并置 ok:false）；apcaLc(text, bg) APCA Lc 参考读数（正=深字浅底）；simulateCvd(hex, type) Machado 2009 色觉模拟（protanopia/deuteranopia/tritanopia，严重度 1.0，线性空间）。APCA 仅作参考值，不用于合规判定。A11y tools (new in W-tb-P36): contrastMatrix(entries) pairwise matrix (symmetric WCAG + directional signed APCA); stepForContrast(base, bg, target) bisects lightness at fixed hue to a target ratio (nearest value with ok:false when unreachable); apcaLc(text, bg) reference APCA Lc readout (positive = dark on light); simulateCvd(hex, type) Machado 2009 simulation (three types, severity 1.0, linear space). APCA is reference-only, never a compliance verdict.

4 · Token 结构（CSS 变量）4 · Token Structure (CSS variables)

导出的 CSS 变量遵循分层命名：Exported variables follow layered naming:

--hia-primary-50 … --hia-primary-900   /* primary, 10 shades */
--hia-secondary-*, --hia-third-*        /* secondary / third families */
--hia-aux0-50 … --hia-auxN-900          /* auxiliary slots (N = index) */
--hia-on-primary / --hia-on-aux0        /* foregrounds (WCAG auto-picked) */
--hia-fs-h1 / --hia-line-height-body    /* typography & line-height tokens (ADR-006) */

运行时（预览区）另有 --p/--s/--t/--a{N} 前缀的快捷变量供 mock 与渐变消费。At runtime the preview area also exposes --p/--s/--t/--a{N} shorthand variables for mocks and gradients.

6 · 桌面端架构与取色6 · Desktop Architecture & Extraction

两端共享同一 scanner bundle（HIA/extractor/dist/browser-scanner.bundle.js，IIFE 自包含），保证评分一致；构建校验脚本断言三端内容哈希一致。Both desktop ends share one scanner bundle (HIA/extractor/dist/browser-scanner.bundle.js, self-contained IIFE) so scores match; a build script asserts bundle hash equality across ends.

  • Electron：隐藏隔离 BrowserWindow 加载目标页 → 稳定化（网络/渲染双重静默）→ 注入 scanner 采集 DOM 证据 → 量化评分；finally 销毁窗口；Electron: a hidden isolated BrowserWindow loads the page → stabilization (network/render) → scanner injection collects DOM evidence → quantified scoring; the window is destroyed in finally;
  • Tauri：Rust 后端 chromiumoxide launch（显式无头）→ CDP Fetch 域逐请求 SSRF 裁决（重定向每跳 DNS 深度校验，命中即阻断）→ 采集后 Browser.close 带超时护栏，函数返回经 Drop/kill_on_drop 强杀子进程，杜绝残留窗口；Tauri: Rust chromiumoxide launch (explicit headless) → CDP Fetch-domain per-request SSRF adjudication (DNS deep checks on every redirect hop) → after capture, Browser.close with timeout guards; returning drops the Browser and kills the child (kill_on_drop), so no leftover windows;
  • SSRF 防线：协议白名单 → 私网/保留 IP 字面量 → 连接时 DNS 深度解析（fail-closed）→ CDP 逐请求裁决（Electron 为 webRequest 同口径）。SSRF lines: scheme allowlist → private/reserved IP literals → connect-time DNS resolution (fail-closed) → per-request CDP adjudication (Electron enforces the same bar via webRequest).
